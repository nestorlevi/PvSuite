          01O que é a PV Suite

          A PV Suite é um conjunto de ferramentas para criar sistemas de supervisão (IHM / SCADA) baseado no pvbrowser. Funciona como um navegador web, mas para aplicações industriais:

          ComponenteO que faz
          pvserverO programa que você escreve (em C++, ou Lua / Python). Define as telas ("máscaras") e a lógica: o que é mostrado, o que acontece ao clicar num botão. Roda no servidor.
          pvbrowserO cliente. Conecta-se a um pvserver (porta 5050 por padrão) e mostra suas telas. Vários PCs podem se conectar ao mesmo pvserver.
          pvdevelopO ambiente de desenvolvimento: editor de código, designer gráfico de telas (Designer), compilação e configuração dos daemons.
          daemonsProgramas que se comunicam com os CLPs (Modbus, Siemens S7, ...) e deixam os dados numa memória compartilhada. O pvserver os lê dali e envia as escritas por um mailbox.
          rllibBiblioteca com as classes para os daemons, memória compartilhada, sockets, threads, arquivos, etc.
           CLP ──(Modbus / S7)──> daemon ──> memória compartilhada ──> pvserver ──(rede)──> pvbrowser
                                   ^                                    │
                                   └───────────── mailbox ──────────────┘   (escritas)

          Separar a comunicação (daemon) da interface (pvserver) faz com que uma falha de comunicação não bloqueie as telas e que vários pvservers possam usar os mesmos dados.

          02Instalação

          2.1Windows

          Executar PvSuite-<versão>-Setup-win64.exe (baixado de github.com/nestorlevi/PvSuite/releases). O instalador tem estes componentes:

          ComponenteConteúdoPasta
          pvbrowser (cliente)pvbrowser com navegador web (Qt WebEngine). É tudo o que precisa um PC que só se conecta a pvservers.<destino>\win-msvc\bin
          Suíte de desenvolvimento (pvdevelop)pvdevelop, ferramentas da rllib, bibliotecas para compilar pvservers (MinGW e Visual Studio), documentação e exemplos.<destino>\win-mingw\bin
          Bibliotecas para MinGW 8.1 (Qt 5.15) (opcional)librllib e libserverlib compiladas com MinGW 8.1 de 64 bits (mingw81_64) e de 32 bits (mingw81_32), para continuar compilando projetos anteriores (Qt 5, de 32 ou 64 bits) com MinGW 8.1 e Qt 5.15.2, e depois levá-los ao MinGW do Qt 6. Não inclui o compilador nem o Qt: instalam-se com o instalador do Qt.<destino>\win-mingw\bin\mingw81_64, mingw81_32
          Arquivos comunsDocumentação, exemplos e cabeçalhos do pvserver e da rllib.<destino>\doc, ejemplos

          Em um PC que só se conecta a pvservers (posto de operação) pode-se desmarcar a suíte de desenvolvimento. O destino padrão é C:\PVSuite. O instalador cria a variável SUITEDIR, adiciona win-mingw\bin ao PATH do usuário e cria atalhos para o pvdevelop e o pvbrowser.

          Cada pasta tem seu próprio Qt: o pvbrowser usa o do Visual Studio (por causa do Qt WebEngine) e o pvdevelop o do MinGW. Por isso ficam em pastas separadas; não se deve misturar seus arquivos.

          Ajuda > Buscar atualizações (pvdevelop e pvbrowser) consulta a última versão publicada no GitHub (github.com/nestorlevi/PvSuite/releases) e oferece baixar o instalador. O pvdevelop também verifica uma vez por semana ao iniciar (pode ser desativado no mesmo menu).

          Compilador para os projetos

          Para compilar os pvservers é preciso um compilador (não é preciso para usar o pvbrowser nem para pvservers em Lua):

          • MinGW (padrão): o do Qt 6.9, C:\Qt\Tools\mingw1310_64 (instalado com o instalador do Qt).
          • Visual Studio 2022 (opcional): Build Tools ou Community.
          • MinGW 8.1 com Qt 5.15.2 (opcional, para projetos anteriores): de 64 bits C:\Qt\Tools\mingw810_64 e C:\Qt\5.15.2\mingw81_64; de 32 bits C:\Qt\Tools\mingw810_32 e C:\Qt\5.15.2\mingw81_32. É preciso marcar o componente "Bibliotecas para MinGW 8.1" ao instalar e escolher esse MinGW no pvdevelop. O .pro do projeto escolhe sozinho as bibliotecas (mingw81_64 ou mingw81_32) conforme o compilador, com uma linha a mais (equals(QMAKE_GCC_MAJOR_VERSION, 8):contains(QT_ARCH, i386):PVB_MINGWLIB = $(PVBDIR)/win-mingw/bin/mingw81_32), que o pvdevelop acrescenta sozinho aos projetos que já tinham a de mingw81_64. Ao trocar de MinGW (por exemplo de GCC 13 para MinGW 8.1 de 32 bits), o pvb_build.bat apaga os restos da compilação anterior (.qmake.stash, os Makefile.win*, os .o e o .exe do projeto) e compila de novo.
          • Se o pvserver usa Qt (por exemplo QT += sql), também o kit do Qt do mesmo compilador (C:\Qt\6.9.2\mingw_64 ou msvc2022_64).

          As pastas são configuradas no pvdevelop: Ação > Compilador... (ver capítulo 6).

          2.2Linux

          O instalador PvSuite-<versão>-Setup-linux-x64.run (chmod +x e executá-lo) instala em /opt/pvb com links em /usr/bin e /usr/lib. Pode-se desmarcar "Bibliotecas Qt incluídas" para usar o Qt 6 do sistema (com Qt WebEngine). Se faltarem bibliotecas do desktop (xcb, WebEngine), o instalador avisa: sudo sh /opt/pvb/terceros/preparar_linux.sh as instala (apt, dnf ou zypper). Os pvservers são compilados com g++ e make: sudo sh /opt/pvb/terceros/preparar_linux.sh -compilar.

          03pvdevelop: o ambiente de desenvolvimento

          No Windows é aberto com o atalho pvdevelop6 (executa start_pvdevelop.bat, que prepara o ambiente). No Linux com pvdevelop.

          3.1Criar um projeto

          1. Arquivo > Novo pvserver (Ctrl+N): escolha uma pasta vazia e o nome (por exemplo pvs).
          2. O pvdevelop gera o projeto:
            ArquivoPara quê
            pvs.proProjeto do qmake (bibliotecas, arquivos).
            main.cppInício do pvserver e escolha da máscara inicial.
            pvapp.hDeclarações comuns (inclua aqui os .h dos daemons).
            mask1.cppTela 1, gerada pelo Designer. Não edite à mão.
            mask1_slots.hLógica da tela 1: é aqui que se programa.
          3. Ação > Inserir máscara (Ctrl+I) adiciona mais telas.

          3.2Vistas e barras de ferramentas

          AtalhoAção
          Ctrl+EEditor de código
          Ctrl+DDesigner (desenho da tela)
          Ctrl+MCompilar o projeto
          Ctrl+TExecutar o pvserver
          Ctrl+PAbrir o pvbrowser (conectado ao pvserver)
          Ctrl+F / Ctrl+RLocalizar / Substituir
          Ctrl+S, Ctrl+BSalvar, backup
          Ctrl+H / F1Manual / ajuda da janela atual
          Ctrl+JMostrar ou ocultar o console de compilação

          No editor aparece a barra Compilação (compilador dos projetos) e no Designer a barra Alinhar (alinhar widgets). Cada barra só aparece na sua vista.

          3.3Texto preditivo

          Enquanto se digita no editor aparecem sugestões (funções do pvserver, palavras do projeto). São aceitas com Enter ou Tab; Ctrl+Espaço as mostra quando se quiser. Desativa-se em Ação > Compilador...

          3.4Idioma

          O pvdevelop e o pvbrowser estão em português, espanhol, inglês e alemão. Por padrão usam o idioma do sistema (inglês, se não for nenhum desses). Para escolher outro: no pvdevelop o menu Idioma, no pvbrowser Arquivo > Idioma. A mudança vale a partir da próxima vez que o programa for aberto. O instalador também usa o idioma do sistema.

          As traduções são arquivos do Qt Linguist que podem ser editados ou ampliados: pvdevelop/translations/pvdevelop_xx.ts e pvbrowser/translations/pvbrowser_xx.ts (abrem-se com o linguist; ao compilar são incluídas no programa). Este manual também está em Manual_PvSuite (espanhol), _en e _de.

          3.5Console de compilação

          Ctrl+M, Ctrl+T e o botão Compilar dos daemons compilam num painel embaixo do pvdevelop, sem janelas à parte (Ação > Console de compilação ou Ctrl+J o mostra ou oculta; pode ser movido ou destacado). Os erros aparecem em vermelho e os avisos em laranja; com clique duplo num erro o arquivo abre nessa linha, e no editor as linhas com erro ficam marcadas (passando o mouse se vê a mensagem). Ctrl+T, se compilou bem, executa o pvserver. No Linux ele abre numa janela do terminal do sistema (x-terminal-emulator, qterminal, konsole, gnome-terminal, xfce4-terminal, lxterminal, mate-terminal ou xterm) que se fecha como qualquer janela; o Ctrl+T fecha antes o pvserver anterior do projeto. Sem terminal, roda dentro do painel de compilação e o botão Parar o fecha. O texto preditivo também sugere os nomes dos widgets das máscaras e dos tags dos daemons (PLC1_Motor1, PLC1_SYS...).

          O console aumenta ou diminui arrastando a sua borda ou com as setas da sua barra, e o botão das duas janelas o separa numa janela à parte. Na lista do texto preditivo um ícone indica o que é cada palavra: W widget, T tag, D daemon, f função do pvserver, C classe da rllib. Ação > Inserir função inclui os tags (com o nome de um daemon e de um tag do projeto) e os tags de sistema.

          3.6Abas de documentos

          Sobre a área de trabalho há uma barra de abas: cada uma mostra uma tela no Designer ou um arquivo no editor. O que se abre pela lista de telas, pelos botões do editor ou pelo combo Tela do Designer substitui o documento da aba atual. Para deixá-lo aberto e olhar outro é preciso uma aba nova:

          • + (à direita das abas): escolhe outro arquivo do projeto e o abre em uma aba nova.
          • Clique direito sobre uma tela da lista: Abrir em nova aba (Designer) ou Abrir maskN_slots.h em nova aba. Se já estava aberto, passa para essa aba.
          • As abas se reordenam arrastando. Um ponto laranja no lugar do X indica alterações sem salvar; Salvar tudo salva todas as modificadas.
          • Cada aba do editor mantém seu próprio histórico de Ctrl+Z: ao voltar a ela continua-se desfazendo o que foi digitado ali, não o de outro arquivo.
          • Se um arquivo desaparece do disco, sua aba é fechada e a barra de estado avisa.

          3.7Recuo e formatação do código

          Ação > Compilador... tem o ajuste Recuo: 2, 3, 4 ou 8 espaços por nível, ou tabulação. São usados por:

          • Tab insere um nível. Com várias linhas selecionadas, acrescenta um nível a todas as que têm texto; Shift+Tab remove um nível (em uma linha ou na seleção).
          • Enter depois de { recua a linha seguinte.
          • Clique direito > Formatar código (das linhas selecionadas ou do arquivo todo): refaz o recuo conforme as chaves { } de C/C++. Respeita as linhas de pré-processador (#), os comentários /* */ e as continuações de uma instrução com parêntese aberto. Depois de if, for, while ou else sem chave, a linha seguinte ganha um nível a mais.

          As tabulações que um arquivo já tiver aparecem com a mesma largura do nível escolhido (com tabulação: 4).

          04O Designer: desenhar telas

          4.1Inserir widgets

          • Clique duplo em um lugar vazio, ou Shift+clique: abre Inserir widget (botões, rótulos, imagens, tabelas, gráficos, TextBrowser, ...). Para imagens há um botão para escolher o arquivo.
          • Ctrl+Shift+clique: insere novamente o último tipo de widget.
          • Cada widget tem um nome (objectName). Com esse nome ele é usado no código: pvSetText(p, Titulo, "Olá").

          4.2Selecionar, mover e propriedades

          • Arrastar o mouse sobre uma área vazia seleciona vários widgets. Ctrl+clique adiciona ou remove um.
          • Setas: movem; Ctrl+setas: mudam o tamanho. Ctrl+Z: desfaz o último movimento.
          • P ou Alt+clique: propriedades do widget. Del: exclui.

          4.3Alinhar

          Com vários widgets selecionados, a barra Alinhar os alinha à esquerda, à direita, em cima ou embaixo (a referência é o primeiro selecionado) e distribui o espaço horizontal ou vertical entre os extremos.

          4.4Copiar e colar

          Ctrl+C / Ctrl+V copiam os widgets selecionados, de qualquer tipo, incluindo o conteúdo dos contêineres (por exemplo um Frame com tudo o que há dentro). Ao colar, cada cópia mantém seu nome com um número: Motor → Motor_1, Motor_2.

          05Programar um pvserver

          5.1Os slots

          Cada tela tem em maskN_slots.h funções que são chamadas a cada evento:

          SlotQuando é chamado
          slotInit(p, d)Ao abrir a tela: valores iniciais, baixar imagens.
          slotNullEvent(p, d)Periodicamente (a cada 1 s por padrão, -sleep=500 na linha de comando): atualizar os valores do processo.
          slotButtonEvent(p, id, d)Clique num botão (também Pressed e Released).
          slotTextEvent(p, id, d, text)Um texto mudou (LineEdit) ou houve navegação num TextBrowser.
          slotSliderEvent(p, id, d, val)Um slider, dial ou spinbox foi movido.
          slotCheckboxEvent, slotRadioButtonEventCaixas de seleção e botões de opção.
          slotTableTextEvent, slotTableClickedEventTabelas.
          slotMouse...Event, slotKeyboardEventMouse e teclado (desenhos SVG, gráficos).

          O parâmetro id é o nome do widget; p identifica a conexão do cliente; d são os dados da tela.

          5.2Dados da tela: DATA

          Cada tela tem sua estrutura DATA (uma para cada cliente conectado). O pvdevelop a gera dentro de um namespace { }, assim cada máscara tem a sua mesmo que tenham funções com o mesmo nome:

          namespace { // DATA propia de esta mascara (DATA própria desta máscara)
typedef struct
{
  int contador;
  int modo() { return contador % 2; }
}
DATA;
} // namespace
          Em projetos antigos, se duas máscaras têm funções dentro de DATA, adicione o namespace { } à mão. Sem ele, o linker pode usar a função de outra máscara (com MSVC o pvserver fecha).

          5.3Exemplos

          Mostrar um valor e mudar a cor

          static int slotNullEvent(PARAM *p, DATA *d)
{
  float t = lerTemperatura();
  pvPrintf(p, LabelTemp, "%.1f °C", t);
  if(t > 80) pvSetPaletteBackgroundColor(p, LabelTemp, 255, 0, 0);  // vermelho
  else       pvSetPaletteBackgroundColor(p, LabelTemp, 0, 200, 0);  // verde
  return 0;
}

          Um botão que muda de tela

          static int slotButtonEvent(PARAM *p, int id, DATA *d)
{
  if(id == BotaoAlarmes) return 2;   // o número da máscara a mostrar
  return 0;
}

          Imagens e arquivos

          static int slotInit(PARAM *p, DATA *d)
{
  pvDownloadFile(p, "Imagens/fundo.png");  // o cliente o guarda na sua pasta temporária
  pvSetImage(p, Fundo, "fundo.png");
  return 0;
}
          Os caminhos relativos são procurados na pasta a partir da qual o pvserver é executado. Execute-o a partir da pasta do projeto (o pvdevelop já faz isso), não a partir de release.

          Mensagem de confirmação

          // tipo: BoxInformation, BoxWarning ou BoxCritical
pvMessageBox(p, BotaoParar, BoxWarning, "Parar a bomba?", MessageBoxYes, MessageBoxNo, 0);
// a resposta chega a slotSliderEvent(p, BotaoParar, d, val) com val = MessageBoxYes ou MessageBoxNo

          A lista completa de funções está na referência de programação (doc/pvslib).

          06Compilar e executar os projetos

          6.1Escolher o compilador

          A barra Compilação (vista Editor) tem o seletor MinGW / MSVC. Um compilador que não é encontrado na pasta configurada aparece desabilitado. As pastas, o número de processadores e o texto preditivo são configurados em Ação > Compilador...:

          CampoExemplo
          Visual Studio 2022C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools
          Qt para MSVC (opcional)C:\Qt\6.9.2\msvc2022_64 (se o projeto usa Qt)
          jom (opcional)compila em paralelo com MSVC
          MinGWC:\Qt\Tools\mingw1310_64
          Qt para MinGW (opcional)C:\Qt\6.9.2\mingw_64
          Processadoresarquivos compilados ao mesmo tempo

          O botão Detectar automaticamente procura o Visual Studio, o MinGW, o Qt e o jom.

          6.2Compilar e testar

          1. Ctrl+M compila. Os erros aparecem na janela de compilação.
          2. Ctrl+T executa o pvserver (porta 5050).
          3. Ctrl+P abre o pvbrowser conectado a localhost.

          Se o projeto usa Qt (QT += sql, core, ...) é preciso configurar o kit Qt do compilador; senão, basta o compilador.

          6.3O arquivo .pro

          O pvdevelop adiciona blocos para MinGW (win32-g++) e Visual Studio (win32-msvc*). Se forem usadas funções do Windows que não estão nas bibliotecas padrão do MSVC (por exemplo ShellExecute), adicione no bloco win32-msvc*:

          LIBS += -lshell32

          07pvbrowser: o cliente

          Digite o endereço do pvserver na barra (por exemplo 192.168.1.10 ou pv://192.168.1.10:5050) e pressione Enter. As opções (tela cheia, zoom, pasta temporária) estão no menu; o idioma em Arquivo > Idioma.

          7.1Páginas web e Grafana

          O widget TextBrowser é um navegador completo (Qt WebEngine): mostra páginas web, HTML com JavaScript e painéis do Grafana. No pvserver:

          pvSetSource(p, Navegador, "https://www.exemplo.com");          // uma página
pvDownloadFile(p, "Ajuda/manual.html");                         // um arquivo do projeto
pvSetSource(p, Navegador, "manual.html");
pvSetText(p, Navegador, "<h1>Estado</h1><p>Tudo OK</p>");     // HTML gerado

          Um painel do Grafana incorporado (em grafana.ini: allow_embedding=true e acesso anônimo somente leitura):

          pvSetSource(p, Grafico,
  "http://192.168.1.10:3000/d-solo/abc123/planta?orgId=1&panelId=2&refresh=5s&theme=light");

          O Grafana é indicado para históricos e análises; para valores em tempo real os gráficos próprios do pvbrowser (Qwt) são melhores.

          08Comunicação com CLPs: daemons

          Os daemons são configurados pelo menu Daemon do pvdevelop: Modbus, Siemens TCP, PPI. Cada um tem um arquivo de configuração (.mkmodbus, .mksiemens). O botão Compilar gera o daemon (C++) e o .h que o pvserver usa, e o compila.

          Um arquivo novo guarda a memória compartilhada e o mailbox na pasta automation do projeto, com caminho relativo: shared_memory=automation/shm/PLC1.shm e mailbox=automation/mbx/PLC1.mbx. Assim o projeto pode ser movido para outra pasta ou PC sem mudar nada. Os programas são executados a partir da pasta do projeto (pvdevelop e os atalhos fazem isso sozinhos); as pastas são criadas sozinhas. Aceita-se \, \\ ou / (no Linux, /). No Windows o nome do mailbox vale para todo o PC: dois projetos com um daemon do mesmo nome não podem rodar ao mesmo tempo. Se um arquivo do daemon já tem tags, ao abri-lo também se abre o editor de tags; ao fechá-lo fica a janela do daemon para compilar.

          8.1Modbus: configuração

          shared_memory=c:\automation\shm\plc1.shm
mailbox=c:\automation\mbx\plc1.mbx
communication=socket          # socket (Modbus TCP) ou serial (RTU / ASCII)
tcpadr=192.168.1.20
tcpport=502
#tty=COM1  baudrate=9600  parity=0  protocol=0

          8.2A forma clássica: ciclos

          Continua podendo ser usada como antes: cada cycle lê um bloco fixo de registradores.

          cycle1 slave=1 function=3 start_adr=0 num_register=50

          No pvserver lê-se por posição: PLC1.readShort(PLC1_CYCLE1_BASE, 49). Os projetos existentes funcionam sem mudanças. A forma recomendada agora são os tags (próximo capítulo): podem ser combinados com os ciclos no mesmo arquivo.

          8.3Compilar o daemon

          Compilar gera o código e o compila na sua própria janela (como Ctrl+M), com MinGW ou Visual Studio conforme o compilador escolhido: o pvdevelop não fica bloqueado enquanto compila. Se o daemon estiver em execução, a janela pergunta se deve fechá-lo (o seu .exe não pode ser substituído enquanto roda). Fechar salva o arquivo e compila só se ele mudou desde a última compilação (ou se falta o .exe). No Windows isso é feito por win-mingw\bin\pvb_make_daemon.bat nome [ppi]; no Linux, por uma janela xterm.

          8.4Mensagens no console

          O daemon numera os seus ciclos. No editor de tags, Console do daemon escolhe o que ele escreve na sua janela (console= no arquivo):

          NívelO que mostra
          Silencioso (quiet, -q)Só erros: quando um bloco deixa de ser lido e quando volta, e os erros de escrita.
          Normal (normal, -n)O mesmo e um resumo a cada console_interval segundos (10).
          Detalhado (verbose, -v)Cada bloco lido com o número do ciclo, o escravo, o endereço, o resultado e quanto demorou; e o fim de cada ciclo.
          [ciclo 1234] bloque 2/5 esclavo 1 FC3 40300..40301 ok 1 ms
[ciclo 1234] fin: bloques ok=5 error=0, 3 ms
[ciclo 1300] 66 ciclos en 10 s, ultimo 1 ms (max 12), bloques ok=5 error=0, errores lectura=0 (0 nuevos) escritura=0

          Ao executar o daemon, -q, -n ou -v mudam o nível sem compilar de novo.

          8.5Tags de sistema

          Os daemons Modbus e Siemens deixam no fim da memória compartilhada o estado da comunicação. O pvdevelop os acrescenta ao .h como PLC1_SYS:

          TagTipoSignificado
          ComunicacionboolTodos os blocos do último ciclo foram lidos corretamente
          ComunicacionParcialboolAlgum bloco foi lido corretamente e algum falhou
          ConectadoboolConexão aberta (socket ou porta serial)
          BloquesOk, BloquesErroruintResultado do último ciclo
          CicloudintNúmero do ciclo
          TiempoCiclo, TiempoCicloMaxudintDuração do último ciclo e a máxima, em ms

if(!PLC1.daemonAlive(PLC1_SYS.Ciclo))     pvSetText(p, lbEstado, "O daemon nao esta funcionando");

          daemonAlive(tag, segundos) (5 por padrão) indica se Ciclo avançou nesses segundos: se o daemon parar, os outros tags ficam com o último valor. Sem prefixo: SYS.Comunicacion (com using namespace tags_PLC1;).

          Os tags de sistema vão depois dos ciclos e dos tags: a memória compartilhada cresce, e o daemon e o pvserver são compilados com o mesmo .h, como sempre.

          8.6Simulação

          Para testar com um simulador sem mudar o IP nem recompilar, no mesmo .mkmodbus:

          tcpadr=192.168.1.20               # o CLP
simulation_tcpadr=127.0.0.1       # o simulador
simulation_tcpport=502

          O daemon executado com -sim (ou com a variável de ambiente PVB_SIMULATION=1) conecta-se ao simulador; senão, ao CLP. Os tags, a memória compartilhada e o .h são os mesmos, então o pvserver não muda. Serve também com um daemon serial (RTU): em simulação usa Modbus TCP. Já não é preciso um segundo arquivo (PLC1_Simulacion.mkmodbus) com outros nomes de tags. Daemon > Modbus carrega o primeiro .mkmodbus da pasta do projeto (com Abrir escolhe-se outro).

          8.7Monitor de tags

          Daemon > Monitor de tags... mostra ao vivo o valor e a qualidade dos tags de cada daemon (lê os .tagmap e a memória compartilhada, só leitura), com um filtro por nome: serve para depurar sem mexer no pvserver. Os botões Iniciar daemon e Iniciar em simulação o executam na sua janela, normal ou com -sim.

          Também está no ícone da barra Projeto, no Designer e no editor. Em cima escolhe-se o Daemon (um .tagmap da pasta do projeto) e o Filtro; Pausa congela a tabela. Colunas: Tag, Valor, Qualidade, Forçado, Tipo, Descrição (clique no título para ordenar). A qualidade é bem, erro ou parado: se SYS.Ciclo não avança em 5 segundos, o monitor avisa em vermelho DAEMON PARADO e os valores são os últimos que o daemon deixou.

          Escrever e forçar valores

          Escolher um tag da lista, digitar o Valor e usar:

          BotãoO que faz
          EscreverEscreve o valor uma vez (o PLC pode alterá-lo depois).
          ForçarEscreve o valor de novo cada vez que ele muda (no máximo uma vez por segundo) até Liberar ou fechar o monitor. A linha fica amarela e a coluna Forçado indica.

          Somente podem ser escritos os tags rw=1. Na primeira vez de cada sessão pede confirmação, porque com o daemon real (sem simulação) escreve-se na máquina. Escrever e Forçar só são habilitados se o daemon foi compilado com esta versão do pvdevelop (o .tagmap traz mailbox= e os endereços); se não, a linha de estado avisa: compilar o daemon de novo. As escritas vão pelo mailbox do daemon, igual às do pvserver.

          09Tags: variáveis com nome

          Um tag é uma variável do CLP com nome, endereço e tipo. O pvdevelop agrupa os endereços contíguos ou próximos em blocos e o daemon lê cada bloco num só pedido (como os SCADA comerciais).

          9.1Editor de tags

          Na janela do daemon, botão Tags.... A aba Variáveis tem a tabela de tags e os ajustes; a aba Estruturas define tipos compostos (capítulo 10). O botão Verificar mostra os blocos de leitura. As variáveis podem ser salvas no arquivo do daemon ou num CSV (editável com Excel); também há Importar/Exportar CSV.

          O seletor Daemon de cima lista os daemons do mesmo protocolo que há na pasta do projeto: ao escolher outro, o editor pergunta se as alterações são salvas e abre os tags do outro daemon sem passar pela janela dele.

          9.4Escrita de bits

          Um bit de um holding register (40300.15) pode ser escrito de duas formas (ajuste Escrita de bits):

          • Ler-modificar-escrever (padrão): o daemon lê o registrador, altera o bit e o escreve. Funciona com qualquer CLP.
          • Função 22 (Mask Write Register): o CLP altera o bit. Só se o CLP a suportar.

          9.5No arquivo .mkmodbus

          address_notation=modicon

          Colunas do CSV: name;address;type;count;stride;rw;slave;scan;scale;offset;order;description

          9.6Como o daemon lê

          Ciclos e tags ao mesmo tempo

          Os cycle e os tag são usados ao mesmo tempo. A cada volta o daemon:

          1. lê os cycle, em ordem (seus dados ficam no início da memória compartilhada, PLC1_CYCLE1_BASE, ...);
          2. atualiza o contador de vida e os de erros;
          3. lê os blocos dos tags (os que têm scan só quando chega a vez deles);
          4. espera, se necessário, para que a volta dure pelo menos cycletime ms.

          Sem tags o daemon funciona como antes (gera a mesma memória compartilhada). Se forem usados só tags, convém apagar os cycle: o modelo traz ciclos de exemplo para os escravos 1 a 7, e um escravo que não existe faz esperar o tempo de resposta a cada volta, o que também atrasa a leitura dos tags. Se ciclos e tags leem os mesmos registradores, eles são lidos duas vezes (funciona, mas é tráfego a mais).

          Escala e Offset

          valor = bruto × Escala + Offset. Aplica-se em getReal() e, ao contrário, em setReal(); getInt() devolve o valor bruto. Exemplos:

          O CLP enviaEscalaOffsetResultado
          Décimos de grau (253)0.1025.3
          0 a 27648 para −50 a 150 °C0.0072338−5027648 → 150
          Milésimos de bar0.00101500 → 1.5

          Scan e agrupamento

          Dois tags são lidos no mesmo pedido só se coincidem em escravo, área (holding, input, coil, discreta; no S7 a área e o número do DB) e scan. Tags contíguos com scan diferente vão em pedidos separados, cada um no seu ritmo:

          tag name=A address=%MW0              # scan 0
tag name=B address=%MW1              # scan 0     -> A e B: um pedido a cada volta
tag name=C address=%MW2 scan=1000    # outro pedido, a cada 1 s

          O scan é um mínimo: o bloco é lido na primeira volta em que se passaram pelo menos esses milissegundos. Se uma volta dura 300 ms, um tag com scan=1000 é lido a cada 1200 ms aproximadamente, e um scan menor que a volta equivale a 0. O botão Verificar mostra os blocos e com que frequência cada um é lido.

          Tempos: porta serial e TCP

          O daemon faz um pedido de cada vez. Cada pedido leva:

          • a espera antes do pedido (idletime): na serial, 3,5 caracteres como exige o Modbus RTU (4 ms a 9600 baud, no mínimo 2 ms); com TCP, 0;
          • a transmissão: a 9600 baud cada byte leva cerca de 1 ms (ler 8 registradores: uns 30 ms);
          • a resposta do escravo: tipicamente 5 a 20 ms.

          Por isso agrupar ajuda tanto na serial: 8 registradores contíguos num pedido levam uns 40 ms; em 8 pedidos, uns 300. O scan não acelera a comunicação: distribui o tempo, deixando a linha livre para os valores lidos a cada volta. As escritas também ocupam a linha.

          Ajustes do .mkmodbus:

          AjustePadrãoPara quê
          idletime=serial: 3,5 caracteres; TCP: 0ms antes de cada pedido. Para equipamentos lentos ou conversores serial/Ethernet que precisem (idletime=41 é a espera das versões anteriores a 9600 baud).
          cycletime=50Duração mínima de uma volta em ms: o daemon não lê com mais frequência que isso (não sobrecarrega o CLP nem a CPU). cycletime=0: sem pausa.

          9.7Endereço no PLC

          O monitor de tags mostra, na coluna Endereço, onde cada tag está no PLC: %MW0.0 (Modbus) ou DB10.DBX0.1 (Siemens). O daemon o escreve no .tagmap (plcaddr=); uma estrutura mostra o do seu primeiro membro. O filtro do monitor também busca por endereço. É preciso regerar os daemons para que os .tagmap o tragam.

          9.8Ordenar as tabelas

          No editor de tags (as tabelas de tags e de membros das estruturas) um clique no título de uma coluna ordena por ela; outro clique inverte a ordem.

          • A ordem é numérica ou natural (Motor2 antes de Motor10) e as células vazias vão para o fim. Combos e caixas ordenam pelo valor.
          • Ordenar só muda a visão: a ordem dos tags nos arquivos não muda, a menos que se use Subir ou Descer.

          10Estruturas e vetores

          10.1Vetores

          Com Quantidade > 1 a variável é um vetor: Temp[0], Temp[1], ... com endereços consecutivos, ou a cada Passo registradores (bytes no S7). Em vetores de bits o passo é em bits.

          tag name=Temp   address=40100   type=real count=10            # Temp[0..9]: 40100, 40102, ...
tag name=Alarme address=40200.0 type=bool count=32            # 32 bits: 40200.0 ... 40201.15
tag name=Nivel  address=40300   type=int  count=4 stride=10   # 40300, 40310, 40320, 40330

          10.2Estruturas

          Uma estrutura é um tipo composto, como os UDT dos CLPs. É definida uma vez (aba Estruturas) e usada como tipo de uma ou várias variáveis. Cada membro tem uma Posição relativa ao início (registradores no Modbus, bytes no S7; com .bit para um bool). Sem posição, o membro vem depois do anterior (os bool seguintes ocupam o bit seguinte).

          struct name=Motor desc="Motor da bomba"
member name=Marcha     at=0.0 type=bool rw=1
member name=Falha      type=bool              # 0.1 (em seguida)
member name=Velocidade at=2   type=real rw=1
member name=Corrente   type=int scale=0.1     # 4
member name=Alarme     type=bool count=3      # 5.0, 5.1, 5.2
end
tag name=Bomba1 address=40500 type=Motor
tag name=Bombas address=40600 type=Motor count=4 stride=10    # um motor a cada 10 registradores

          No pvserver:

          float v = PLC1.getReal(PLC1_Bomba1.Velocidade);
PLC1.setBool(PLC1_Bombas[2].Marcha, 1);
for(int i=0; i<PLC1_Bombas_COUNT; i++)
  pvPrintf(p, Tabela, ...);   // percorrer o vetor

          As posições não precisam ser consecutivas (pode haver lacunas) e as estruturas podem ser usadas em várias variáveis ou em vetores. Cada estrutura é lida num só bloco se seus membros estiverem próximos.

          10.3Estruturas compartilhadas entre daemons

          Se um projeto tem vários daemons (por exemplo dois PLC Modbus e um Siemens) com o mesmo tipo de equipamento, a estrutura Motor é definida uma só vez: na aba Estruturas do editor de tags, marcar Compartilhada com os outros daemons do projeto. A estrutura é guardada em <projeto>.mkstruct e cada arquivo de daemon recebe uma linha structs=<projeto>.mkstruct; se o daemon tem uma estrutura própria com o mesmo nome, essa tem prioridade.

          # pvs.mkstruct
struct name=Motor desc="Motor de bomba"
member name=Marcha    type=bool rw=1
member name=Falla     type=bool
member name=Velocidad type=real rw=1
end

          Com a coluna Em (posição) vazia, a mesma estrutura serve para qualquer protocolo (Modbus e Siemens): os membros vão um após o outro.

          12Uso dos tags no pvserver

          12.1Preparar o projeto

          1. Em pvapp.h: #include "PLC1.h" (o .h gerado pelo pvdevelop).
          2. Em main.cpp, uma vez: rlModbusClient PLC1(PLC1_MAILBOX, PLC1_SHARED_MEMORY, PLC1_SHARED_MEMORY_SIZE);
            (Siemens: rlSiemensTCPClient; mesmos argumentos).
          3. Em cada maskN_slots.h que o use: extern rlModbusClient PLC1;
          4. RLlib > Descomentar rllib adiciona as bibliotecas ao .pro.
          5. O daemon precisa estar em execução (no Windows a partir de um console, ou como serviço).

          12.2Funções

          FunçãoDevolve / faz
          getBool(tag)0 ou 1
          getInt(tag) / getUInt(tag)Inteiro, sem escala
          getReal(tag)Valor com a escala do tag (qualquer tipo)
          quality(tag)1 = lido corretamente; 0 = erro de comunicação
          setBool(tag, v), setInt(tag, v), setReal(tag, v)Escreve (o tag precisa ser RW). setReal aplica a escala ao contrário.
          rlTagFind(PLC1_tags, PLC1_TAG_COUNT, "Bomba1.Velocidade")Procura um tag pelo nome (devolve um ponteiro ou NULL)

          12.3O prefixo PLC1_ e os tags sem prefixo

          As variáveis se chamam PLC1_<nome> (o nome do daemon e um sublinhado) por dois motivos: em cada máscara os widgets também são nomes de C++ (Temp, Motor1, ...) e é comum haver uma variável e um widget com o mesmo nome; e um projeto pode ter vários daemons com tags do mesmo nome (PLC1_Marcha, PLC2_Marcha).

          Para escrever só o nome, o .h traz os mesmos tags no namespace tags_PLC1:

          using namespace tags_PLC1;               // na máscara (maskN_slots.h)

float t = PLC1.getReal(Temp);
PLC1.setBool(Bombas[2].Marcha, 1);
for(int i=0; i<Temp_COUNT; i++) ...

          Se um nome coincide com um widget dessa máscara, o compilador avisa (reference to 'Temp' is ambiguous); aí usa-se a forma completa, PLC1_Temp ou tags_PLC1::Temp. Também é possível usar tags_PLC1::Temp sem o using.

          12.4Exemplo completo

          static int slotNullEvent(PARAM *p, DATA *d)

          13Ações e animações dos widgets (Tags...)

          Um botão pode escrever um tag, um rótulo pode mostrar o valor de um tag e um desenho pode mudar de cor sem escrever uma única linha de código: configura-se no Designer e o pvdevelop gera o código. Tudo o que segue vale para pvservers em C/C++ (não para Lua) e funciona igual no Windows, Linux.

          13.1Abrir o diálogo

          1. No Designer, Alt+clique no widget (ou botão direito > Properties): abre-se o diálogo de Propriedades.
          2. Botão Tags.... Se o widget já tem vínculos, o botão mostra uma marca ✓ e um resumo.
          3. O diálogo Ação e animação de <widget> tem duas abas: Ação (o que acontece ao usar o widget) e Animação (como ele aparece conforme os tags).
          A lista de tags vem dos arquivos .tagmap dos daemons. Se estiver vazia, o diálogo avisa Não há tags: compile antes o daemon (Daemon > Modbus / Siemens TCP, botão Compilar) para que seja gerada. Um tag é escolhido como Fonte:nome (por exemplo PLC1:Motores[0].Marcha); pode-se digitar parte do nome na caixa para filtrar.

          13.2Aba Ação

          Grupo Ao usar o widget: três linhas, Ao clicar, Ao pressionar e Ao soltar. Em cada uma escolhe-se a ação, o tag e, conforme a ação, um valor ou uma tela.

          AçãoO que faz
          NadaNão faz nada.
          Escrever valorEscreve o valor fixo no tag (write:PLC1:Bomba=1).
          Alternar (bool)Inverte o tag (toggle:PLC1:Bomba).
          Somar / SubtrairSoma ou subtrai o valor ao tag (para botões + e −); respeita os limites mínimo e máximo.
          Ir para telaMuda para a máscara indicada (goto:3).
          Voltar / InícioVolta à tela anterior ou à primeira.

          O botão Botão momentâneo preenche as três linhas para escrever 1 ao pressionar e 0 ao soltar (por exemplo "funciona enquanto estiver apertado").

          Opções

          CampoPara que serve
          Escrever o valor digitado emPara LineEdit (o número digitado, com Enter), Slider, Dial, SpinBox (seu valor) e CheckBox (1 ou 0): o tag que recebe o valor.
          Limites (somar, subtrair, digitado)Mínimo e máximo; um valor fora da faixa é cortado ou rejeitado.
          Confirmar antes (clique)Texto de uma pergunta Sim/Não (por exemplo Ligar o motor 1?). Vazio = sem confirmar.
          Somente seCondição sobre outro tag (==, !=, >, >=, <, <=) e a mensagem mostrada se não for cumprida (um intertravamento: "não ligar com a comporta aberta").

          13.5Código próprio

          O slot do widget continua disponível. O código próprio é escrito antes ou depois da linha pvbActions; o de antes pode impedir a ação (retornando um valor), o de depois sempre é executado.           13.6Exemplo passo a passo: botão de partida com indicador

          1. Compilar o daemon (PLC1) para ter seus tags.
          2. No Designer inserir um PushButton btnBomba e um rótulo lblBomba.
          3. btnBomba > Propriedades > Tags...: Botão momentâneo com o tag PLC1:Bomba; Nível mínimo 1.
          4. lblBomba > Tags... > Animação: Texto PLC1:Bomba com formato Parada|Em marcha; Cor 0=#808080;1=#00C000.
          5. Ctrl+S, Ctrl+M (compilar) e Ctrl+T (executar). Abrir o pvbrowser com Ctrl+P.
          Um pvbrowser anterior a esta versão ignora as ordens novas (faixa de alarmes, animação de imagens) sem dar erro; o resto funciona.

          13.7Bits de inteiros e condições

          Uma tela pode usar um bit de um inteiro como se fosse um tag: PLC1:Estado.3 é o bit 3 de PLC1:Estado. Vale em textos, cores, visível, piscar, animações e nas ações toggle: e write:.

          • Leitura: inteiros de tipo byte, int, uint, dint e udint. Escrita: só de 8 e 16 bits. No Modbus se escreve com Mask Write; no Siemens, no byte endereço + tamanho-1-bit/8 (o bit 10 de DBW300 é DBX300.2).
          • O pvdevelop avisa no ATENCION de maskN_pvb.h se o bit é de um real ou bool, está fora de faixa, ou se se quer escrever um bit de 32 bits.
          • No Modbus com ordem de bytes BADC ou DCBA, o bit de um registrador é escrito como bit do registrador, não do valor reordenado.

          Condições

          Onde a tela pede uma condição (Animar enquanto, Visível, Piscar e o somente se das ações) pode-se escrever:

          CondiçãoÉ verdadeira quando
          PLC1:Bombao tag é verdadeiro (diferente de zero)
          !PLC1:Bombao tag é falso
          PLC1:Estado == 2comparação com um valor: ==, !=, >=, <=, >, < (um só = vale como ==)
          PLC1:Estado.3o bit 3 do inteiro está em 1

          14Imagens embutidas

          Normalmente as imagens são distribuídas como arquivos junto ao pvserver e o pvbrowser as baixa. Com imagens embutidas ficam dentro do executável: não é preciso copiar a pasta de imagens para o PC de produção e ninguém pode alterá-las ou apagá-las.

          14.1Como usá-las

          • Uma imagem: Propriedades do widget > caixa Embutir imagem.
          • Todas juntas: Ação > Recursos do projeto.... A tabela tem as colunas Embutir, Arquivo, Tamanho (ordenável) e Usada em. Os botões Marcar as usadas (as que as máscaras usam), Todas e Nenhuma ajudam; Salvar grava a lista.
          • Ao escolher uma imagem de qualquer pasta nas propriedades, o pvdevelop oferece copiá-la para a pasta Image/ do projeto.

          A lista é guardada em <projeto>.pvres (um arquivo por linha). A cada compilação o pvdevelop gera pvresources.cpp com os dados (e o adiciona ao .pro) somente se algo mudou. Em execução o pvserver envia a imagem embutida ao pvbrowser uma vez por conexão, como arquivo temporário, e o pvbrowser o apaga ao fechar.

          # Arquivos embutidos no pvserver (pvdevelop: Ação > Recursos do projeto)
imagenes/off.png
imagenes/on.png
imagenes/luz.gif

          14.2Animação de imagens

          A animação é feita pelo pvbrowser (sem tráfego enquanto anima). Configura-se em Tags... > Animação > Animar enquanto (ver 13.3) ou pelo código:

          pvSetImageAnimation(p, Bomba, "bomba1.png,bomba2.png,bomba3.png", 300);   // quadros e período em ms

          Os .gif animados são reproduzidos sozinhos. Vale somente para pvservers em C/C++.

          15Compilar a suite

          Somente para quem modifica o PV Suite. É preciso o Qt 6.9 (testado com 6.9.2). Compila-se com qmake, em uma pasta à parte (build/, fora do git); também é possível abrir os .pro no Qt Creator, cada um com seu kit.

          SistemaProjetoO que compila
          Linux e macOSpvsuite.proTudo, incluindo o pvbrowser.
          Windows (MinGW)pvsuite.proTudo menos o pvbrowser: rllib, qwt, pvserver, pvdevelop e as ferramentas.
          Windows (MSVC 2022)msvc/pvbrowser-msvc.propvbrowser (o Qt WebEngine não existe para MinGW), rllib.lib e serverlib.lib, para compilar pvservers com o Visual Studio.

          Linux e macOS

          mkdir build && cd build
~/Qt/6.9.2/gcc_64/bin/qmake ../pvsuite.pro CONFIG+=release    # macOS: ~/Qt/6.9.2/macos/bin/qmake
make -j8

          Windows

          No Windows usam-se os dois projetos: a suite com MinGW e o pvbrowser com MSVC.

          rem console com C:\Qt\Tools\mingw1310_64\bin e C:\Qt\6.9.2\mingw_64\bin no PATH
mkdir build\mingw && cd build\mingw
qmake ..\..\pvsuite.pro CONFIG+=release
mingw32-make -j8

rem console "x64 Native Tools" do Visual Studio 2022 com C:\Qt\6.9.2\msvc2022_64\bin no PATH
mkdir build\msvc && cd build\msvc
qmake ..\..\msvc\pvbrowser-msvc.pro CONFIG+=release
nmake

          As bibliotecas ficam junto às suas fontes (rllib/lib, pvserver, qwt/lib). No Windows, o pvdevelop precisa de qwt/lib/qwt.dll e o pvbrowser de msvc/qwt-msvc/lib/qwt.dll junto ao .exe.

          16Solução de problemas

          SintomaCausa e solução
          O pvserver fecha sem mensagem ao abrir o pvbrowser ou ao atualizar (Ctrl+R). Arquivos não encontrados (execute a partir da pasta do projeto, não de release); um fopen sem verificação; ou funções dentro de DATA sem namespace { } (veja 5.2). Para ver onde falha: compile com QMAKE_CXXFLAGS_RELEASE += /Zi e QMAKE_LFLAGS_RELEASE += /DEBUG e execute cdb -g -G .\release\pvs.exe; no erro digite kb.
          'QString' file not found ao compilar com MSVC.O projeto usa Qt: configure "Qt para MSVC" em Ação > Compilador.
          símbolo externo __imp_ShellExecuteA não resolvidoAdicione LIBS += -lshell32 no bloco win32-msvc* do .pro.
          Qt WebEngine não existe para MinGW no Qt CreatorAbra pvbrowser-www-msvc.pro com o kit MSVC (o pvbrowser com web só compila com MSVC).
          Erros de codificação (C4828, C2001) com MSVCArquivos em Latin-1: converta-os para UTF-8, ou adicione CONFIG -= utf8_source.
          Um tag sempre com quality() = 0O daemon não está em execução, o CLP não responde, ou o endereço não existe no CLP (veja os blocos com Verificar).
          Valores real absurdosOrdem das palavras: experimente CDAB em vez de ABCD.
          Ao compilar o daemon: cannot open output file ... Permission deniedO daemon está em execução: fechá-lo (a janela de compilação oferece isso) e compilar de novo.
          Os tags de sistema (PLC1_SYS) não mudamO daemon não está funcionando ou espera a conexão: ver daemonAlive(PLC1_SYS.Ciclo) e a janela do daemon (com -v).
