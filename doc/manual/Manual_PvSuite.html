          01Qué es PV Suite

          PV Suite es un conjunto de herramientas para hacer sistemas de supervisión (HMI / SCADA) basado en pvbrowser. Funciona como un navegador web, pero para aplicaciones industriales:

          ComponenteQué hace
          pvserverPrograma que escribís vos (en C++, o Lua / Python). Define las pantallas ("máscaras") y la lógica: qué se muestra, qué pasa al tocar un botón. Corre en el servidor.
          pvbrowserEl cliente. Se conecta a un pvserver (puerto 5050 por defecto) y muestra sus pantallas. Varias PC pueden conectarse al mismo pvserver.
          pvdevelopEl entorno de desarrollo: editor de código, diseñador gráfico de pantallas (Designer), compilación y configuración de los daemons.
          daemonsProgramas que se comunican con los PLC (Modbus, Siemens S7, ...) y dejan los datos en una memoria compartida. El pvserver los lee de ahí y les manda las escrituras por un mailbox.
          rllibBiblioteca con las clases para los daemons, la memoria compartida, sockets, hilos, archivos, etc.
           PLC ──(Modbus / S7)──> daemon ──> memoria compartida ──> pvserver ──(red)──> pvbrowser
                                   ^                                  │
                                   └──────────── mailbox ─────────────┘   (escrituras)

          Separar la comunicación (daemon) de la interfaz (pvserver) hace que una falla de comunicación no bloquee las pantallas y que varios pvservers puedan usar los mismos datos.

          02Instalación

          2.1Windows

          Ejecutar PvSuite-<versión>-Setup-win64.exe (se baja de github.com/nestorlevi/PvSuite/releases). El instalador tiene estos componentes:

          ComponenteContenidoCarpeta
          pvbrowser (cliente)pvbrowser con navegador web (Qt WebEngine). Es lo único que necesita una PC que solo se conecta a pvservers.<destino>\win-msvc\bin
          Suite de desarrollo (pvdevelop)pvdevelop, herramientas de rllib, bibliotecas para compilar pvservers (MinGW y Visual Studio), documentación y ejemplos.<destino>\win-mingw\bin
          Bibliotecas para MinGW 8.1 (Qt 5.15) (opcional)librllib y libserverlib compiladas con MinGW 8.1 de 64 bits (mingw81_64) y de 32 bits (mingw81_32), para seguir compilando proyectos anteriores (Qt 5, de 32 o 64 bits) con MinGW 8.1 y Qt 5.15.2, y después llevarlos al MinGW de Qt 6. No incluye el compilador ni Qt: se instalan con el instalador de Qt.<destino>\win-mingw\bin\mingw81_64, mingw81_32
          Archivos comunesDocumentación, ejemplos y cabeceras de pvserver y rllib.<destino>\doc, ejemplos

          En una PC que solo se conecta a pvservers (puesto de operación) se puede desmarcar la suite de desarrollo. El destino por defecto es C:\PVSuite. El instalador crea la variable SUITEDIR, agrega win-mingw\bin al PATH del usuario y crea accesos directos a pvdevelop y pvbrowser.

          Cada carpeta tiene su propio Qt: pvbrowser usa el de Visual Studio (por Qt WebEngine) y pvdevelop el de MinGW. Por eso van en carpetas separadas; no hay que mezclar sus archivos.

          Ayuda > Buscar actualizaciones (pvdevelop y pvbrowser) consulta la última versión publicada en GitHub (github.com/nestorlevi/PvSuite/releases) y ofrece bajar el instalador. pvdevelop además lo revisa una vez por semana al iniciar (se desactiva en el mismo menú).

          Compilador para los proyectos

          Para compilar los pvservers hace falta un compilador (no hace falta para usar pvbrowser ni para pvservers en Lua):

          • MinGW (por defecto): el de Qt 6.9, C:\Qt\Tools\mingw1310_64 (se instala con el instalador de Qt).
          • Visual Studio 2022 (opcional): Build Tools o Community.
          • MinGW 8.1 con Qt 5.15.2 (opcional, para proyectos anteriores): de 64 bits C:\Qt\Tools\mingw810_64 y C:\Qt\5.15.2\mingw81_64; de 32 bits C:\Qt\Tools\mingw810_32 y C:\Qt\5.15.2\mingw81_32. Hay que marcar el componente "Bibliotecas para MinGW 8.1" al instalar y elegir ese MinGW en pvdevelop. El .pro del proyecto elige solo las bibliotecas (mingw81_64 o mingw81_32) según el compilador, con una línea más (equals(QMAKE_GCC_MAJOR_VERSION, 8):contains(QT_ARCH, i386):PVB_MINGWLIB = $(PVBDIR)/win-mingw/bin/mingw81_32), que pvdevelop agrega sola a los proyectos que ya tenían la de mingw81_64. Al cambiar de MinGW (por ejemplo de GCC 13 a MinGW 8.1 de 32 bits), pvb_build.bat borra los restos de la compilación anterior (.qmake.stash, los Makefile.win*, los .o y el .exe del proyecto) y compila de nuevo.
          • Si el pvserver usa Qt (por ejemplo QT += sql), también el kit de Qt del mismo compilador (C:\Qt\6.9.2\mingw_64 o msvc2022_64).

          Las carpetas se configuran en pvdevelop: Acción > Compilador... (ver capítulo 6).

          2.2Linux

          El instalador PvSuite-<versión>-Setup-linux-x64.run (chmod +x y ejecutarlo) instala en /opt/pvb con enlaces en /usr/bin y /usr/lib. Se puede desmarcar "Bibliotecas Qt incluidas" para usar el Qt 6 del sistema (con Qt WebEngine). Si faltan bibliotecas del escritorio (xcb, WebEngine), el instalador lo avisa: sudo sh /opt/pvb/terceros/preparar_linux.sh las instala (apt, dnf o zypper). Los pvservers se compilan con g++ y make: sudo sh /opt/pvb/terceros/preparar_linux.sh -compilar.

          03pvdevelop: el entorno de desarrollo

          En Windows se abre con el acceso directo pvdevelop6 (ejecuta start_pvdevelop.bat, que prepara el entorno). En Linux con pvdevelop.

          3.1Crear un proyecto

          1. Archivo > Nuevo pvserver (Ctrl+N): elegir una carpeta vacía y el nombre (por ejemplo pvs).
          2. pvdevelop genera el proyecto:
            ArchivoPara qué
            pvs.proProyecto de qmake (bibliotecas, archivos).
            main.cppArranque del pvserver y elección de la máscara inicial.
            pvapp.hDeclaraciones comunes (incluir aquí los .h de los daemons).
            mask1.cppPantalla 1, generada por el Designer. No editar a mano.
            mask1_slots.hLógica de la pantalla 1: acá se programa.
          3. Acción > Insertar máscara (Ctrl+I) agrega más pantallas.

          3.2Vistas y barras de herramientas

          AtajoAcción
          Ctrl+EEditor de código
          Ctrl+DDesigner (diseño de la pantalla)
          Ctrl+MCompilar el proyecto
          Ctrl+TEjecutar el pvserver
          Ctrl+PAbrir pvbrowser (conectado al pvserver)
          Ctrl+F / Ctrl+RBuscar / Reemplazar
          Ctrl+S, Ctrl+BGuardar, copia de seguridad
          Ctrl+H / F1Manual / ayuda de la ventana actual
          Ctrl+JMostrar u ocultar la consola de compilación

          En el editor aparece la barra Compilación (compilador de los proyectos) y en el Designer la barra Alinear (alinear widgets). Cada barra se muestra solo en su vista.

          3.3Texto predictivo

          Mientras se escribe en el editor aparecen sugerencias (funciones de pvserver, palabras del proyecto). Se acepta con Enter o Tab; Ctrl+Espacio las muestra a pedido. Se desactiva en Acción > Compilador...

          3.4Idioma

          pvdevelop y pvbrowser están en español, inglés, portugués y alemán. Por defecto usan el idioma del sistema (si no es uno de esos, inglés). Para elegir otro: en pvdevelop el menú Idioma, en pvbrowser Archivo > Idioma. El cambio se aplica la próxima vez que se abre el programa. El instalador también usa el idioma del sistema.

          Las traducciones son archivos de Qt Linguist que se pueden editar o ampliar: pvdevelop/translations/pvdevelop_xx.ts y pvbrowser/translations/pvbrowser_xx.ts (se abren con linguist; al compilar se incluyen en el programa). Este manual también está en Manual_PvSuite_en, _pt y _de.

          3.5Consola de compilación

          Ctrl+M, Ctrl+T y el botón Compilar de los daemons compilan en un panel abajo de pvdevelop, sin ventanas aparte (Acción > Consola de compilación o Ctrl+J lo muestra u oculta; se puede mover o despegar). Los errores se ven en rojo y las advertencias en naranja; con doble clic en un error se abre el archivo en esa línea, y en el editor las líneas con error quedan marcadas (pasando el mouse se ve el mensaje). Ctrl+T, si compiló bien, ejecuta el pvserver. En Linux se abre en una ventana de la terminal del sistema (x-terminal-emulator, qterminal, konsole, gnome-terminal, xfce4-terminal, lxterminal, mate-terminal o xterm) que se cierra como cualquier ventana; Ctrl+T cierra antes el pvserver anterior del proyecto. Si no hay terminal, corre dentro del panel de compilación y el botón Detener lo cierra. El texto predictivo también sugiere los nombres de los widgets de las máscaras y de los tags de los daemons (PLC1_Motor1, PLC1_SYS...).

          La consola se agranda o achica arrastrando su borde o con las flechas de su barra, y el botón de las dos ventanas la separa en una ventana aparte. En la lista del texto predictivo un ícono indica qué es cada palabra: W widget, T tag, D daemon, f función de pvserver, C clase de rllib. Acción > Insertar función incluye los tags (con el nombre de un daemon y un tag del proyecto) y los tags de sistema.

          3.6Pestañas de documentos

          Sobre el área de trabajo hay una barra de pestañas: cada una muestra una pantalla en el Designer o un archivo en el editor. Lo que se abre desde la lista de pantallas, los botones del editor o el combo Pantalla del Designer reemplaza el documento de la pestaña actual. Para dejarlo abierto y mirar otro hace falta una pestaña nueva:

          • + (a la derecha de las pestañas): elige otro archivo del proyecto y lo abre en una pestaña nueva.
          • Clic derecho sobre una pantalla de la lista: Abrir en nueva pestaña (Designer) o Abrir maskN_slots.h en nueva pestaña. Si ya estaba abierto, pasa a esa pestaña.
          • Las pestañas se reordenan arrastrándolas. Un punto naranja en lugar de la X indica cambios sin guardar; Guardar todo guarda todas las modificadas.
          • Cada pestaña del editor conserva su propio historial de Ctrl+Z: al volver a ella se sigue deshaciendo lo que se escribió allí, no lo de otro archivo.
          • Si un archivo desaparece del disco, su pestaña se cierra y la barra de estado lo avisa.

          3.7Sangría y formato del código

          Acción > Compilador... tiene el ajuste Sangría: 2, 3, 4 u 8 espacios por nivel, o tabulación. Lo usan:

          • Tab inserta un nivel. Con varias líneas seleccionadas agrega un nivel a todas las que tienen texto; Shift+Tab quita un nivel (en una línea o en la selección).
          • Enter después de { sangra la línea siguiente.
          • Clic derecho > Formatear código (de las líneas seleccionadas o de todo el archivo): vuelve a sangrar según las llaves { } de C/C++. Respeta las líneas de preprocesador (#), los comentarios /* */ y las continuaciones de una instrucción con un paréntesis abierto. Después de if, for, while o else sin llave, la línea siguiente lleva un nivel más.

          Las tabulaciones que ya tenga un archivo se ven del mismo ancho que el nivel elegido (con tabulación, 4).

          04El Designer: diseñar pantallas

          4.1Insertar widgets

          • Doble clic en un lugar vacío, o Shift+clic: abre Insertar widget (botones, etiquetas, imágenes, tablas, gráficos, TextBrowser, ...). Para imágenes hay un botón para elegir el archivo.
          • Ctrl+Shift+clic: inserta otra vez el último tipo de widget.
          • Cada widget tiene un nombre (objectName). Con ese nombre se lo usa en el código: pvSetText(p, Titulo, "Hola").

          4.2Seleccionar, mover y propiedades

          • Arrastrar con el mouse sobre un área vacía: selecciona varios widgets. Ctrl+clic agrega o quita uno.
          • Flechas: mueven; Ctrl+flechas: cambian el tamaño. Ctrl+Z: deshace el último movimiento.
          • P o Alt+clic: propiedades del widget. Supr: borra.

          4.3Alinear

          Con varios widgets seleccionados, la barra Alinear los alinea a la izquierda, derecha, arriba o abajo (toma como referencia el primero seleccionado) y reparte el espacio horizontal o vertical entre los extremos.

          4.4Copiar y pegar

          Ctrl+C / Ctrl+V copian los widgets seleccionados, de cualquier tipo, incluido el contenido de los contenedores (por ejemplo un Frame con todo lo que tiene adentro). Al pegar, cada copia conserva su nombre con un número: Motor → Motor_1, Motor_2.

          05Programar un pvserver

          5.1Los slots

          Cada pantalla tiene en maskN_slots.h funciones que se llaman ante cada evento:

          SlotCuándo se llama
          slotInit(p, d)Al abrir la pantalla: valores iniciales, descargar imágenes.
          slotNullEvent(p, d)Periódicamente (cada 1 s por defecto, -sleep=500 en la línea de comandos): actualizar valores del proceso.
          slotButtonEvent(p, id, d)Clic en un botón (también Pressed y Released).
          slotTextEvent(p, id, d, text)Se cambió un texto (LineEdit) o se navegó en un TextBrowser.
          slotSliderEvent(p, id, d, val)Se movió un slider, dial o spinbox.
          slotCheckboxEvent, slotRadioButtonEventCasillas y botones de opción.
          slotTableTextEvent, slotTableClickedEventTablas.
          slotMouse...Event, slotKeyboardEventMouse y teclado (dibujos SVG, gráficos).

          El parámetro id es el nombre del widget; p identifica la conexión del cliente; d son los datos de la pantalla.

          5.2Datos de la pantalla: DATA

          Cada pantalla tiene su estructura DATA (una por cada cliente conectado). pvdevelop la genera dentro de un namespace { }, así cada máscara tiene la suya aunque tengan funciones con el mismo nombre:

          namespace { // DATA propia de esta mascara
typedef struct
{
  int contador;
  int modo() { return contador % 2; }
}
DATA;
} // namespace
          En proyectos viejos, si dos máscaras tienen funciones dentro de DATA, agregar el namespace { } a mano. Sin él, el enlazador puede usar la función de otra máscara (con MSVC el pvserver se cierra).

          5.3Ejemplos

          Mostrar un valor y cambiar el color

          static int slotNullEvent(PARAM *p, DATA *d)
{
  float t = leerTemperatura();
  pvPrintf(p, LabelTemp, "%.1f °C", t);
  if(t > 80) pvSetPaletteBackgroundColor(p, LabelTemp, 255, 0, 0);  // rojo
  else       pvSetPaletteBackgroundColor(p, LabelTemp, 0, 200, 0);  // verde
  return 0;
}

          Un botón que cambia de pantalla

          static int slotButtonEvent(PARAM *p, int id, DATA *d)
{
  if(id == BotonAlarmas) return 2;   // el número de la máscara a mostrar
  return 0;
}

          Imágenes y archivos

          static int slotInit(PARAM *p, DATA *d)
{
  pvDownloadFile(p, "Imagenes/fondo.png");  // el cliente lo guarda en su carpeta temporal
  pvSetImage(p, Fondo, "fondo.png");
  return 0;
}
          Las rutas relativas se buscan en la carpeta desde la que se ejecuta el pvserver. Ejecutarlo desde la carpeta del proyecto (pvdevelop ya lo hace), no desde release.

          Mensaje de confirmación

          // tipo: BoxInformation, BoxWarning o BoxCritical
pvMessageBox(p, BotonParar, BoxWarning, "¿Detener la bomba?", MessageBoxYes, MessageBoxNo, 0);
// la respuesta llega a slotSliderEvent(p, BotonParar, d, val) con val = MessageBoxYes o MessageBoxNo

          La lista completa de funciones está en la referencia de programación (doc/pvslib).

          06Compilar y ejecutar los proyectos

          6.1Elegir el compilador

          La barra Compilación (vista Editor) tiene el selector MinGW / MSVC. Un compilador que no se encuentra en la carpeta configurada aparece deshabilitado. Las carpetas, la cantidad de procesadores y el texto predictivo se configuran en Acción > Compilador...:

          CampoEjemplo
          Visual Studio 2022C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools
          Qt para MSVC (opcional)C:\Qt\6.9.2\msvc2022_64 (si el proyecto usa Qt)
          jom (opcional)compila en paralelo con MSVC
          MinGWC:\Qt\Tools\mingw1310_64
          Qt para MinGW (opcional)C:\Qt\6.9.2\mingw_64
          Procesadoresarchivos que se compilan a la vez

          El botón Detectar automáticamente busca Visual Studio, MinGW, Qt y jom.

          6.2Compilar y probar

          1. Ctrl+M compila. Los errores aparecen en la ventana de compilación.
          2. Ctrl+T ejecuta el pvserver (puerto 5050).
          3. Ctrl+P abre pvbrowser conectado a localhost.

          Si el proyecto usa Qt (QT += sql, core, ...) hay que configurar el kit de Qt del compilador; si no, alcanza con el compilador.

          6.3El archivo .pro

          pvdevelop agrega bloques para MinGW (win32-g++) y Visual Studio (win32-msvc*). Si se usan funciones de Windows que no están en las bibliotecas por defecto de MSVC (por ejemplo ShellExecute), agregar en el bloque win32-msvc*:

          LIBS += -lshell32

          07pvbrowser: el cliente

          Se escribe la dirección del pvserver en la barra (por ejemplo 192.168.1.10 o pv://192.168.1.10:5050) y se presiona Enter. Las opciones (pantalla completa, zoom, carpeta temporal) están en el menú; el idioma en Archivo > Idioma.

          7.1Páginas web y Grafana

          El widget TextBrowser es un navegador completo (Qt WebEngine): muestra páginas web, HTML con JavaScript y tableros de Grafana. En el pvserver:

          pvSetSource(p, Navegador, "https://www.ejemplo.com");          // una página
pvDownloadFile(p, "Ayuda/manual.html");                         // un archivo del proyecto
pvSetSource(p, Navegador, "manual.html");
pvSetText(p, Navegador, "<h1>Estado</h1><p>Todo OK</p>");     // HTML generado

          Un panel de Grafana embebido (en grafana.ini: allow_embedding=true y acceso anónimo de solo lectura):

          pvSetSource(p, Grafico,
  "http://192.168.1.10:3000/d-solo/abc123/planta?orgId=1&panelId=2&refresh=5s&theme=light");

          Grafana conviene para históricos y análisis; para valores en tiempo real son mejores los gráficos propios de pvbrowser (Qwt).

          08Comunicación con PLC: daemons

          Los daemons se configuran desde el menú Daemon de pvdevelop: Modbus, Siemens TCP, PPI. Cada uno tiene un archivo de configuración (.mkmodbus, .mksiemens). El botón Compilar genera el daemon (C++) y el .h que usa el pvserver, y lo compila.

          Un archivo nuevo guarda la memoria compartida y el mailbox en la carpeta automation del proyecto, con ruta relativa: shared_memory=automation/shm/PLC1.shm y mailbox=automation/mbx/PLC1.mbx. Así el proyecto se puede mover a otra carpeta o PC sin cambiar nada. Los programas se ejecutan desde la carpeta del proyecto (pvdevelop y los accesos directos lo hacen solos); las carpetas se crean solas. Se acepta \, \\ o / (en Linux, /). En Windows el nombre del mailbox vale para toda la PC: dos proyectos con un daemon del mismo nombre no pueden correr a la vez. Si un archivo del daemon ya tiene tags, al abrirlo se abre también el editor de tags; al cerrarlo queda la ventana del daemon para compilar.

          8.1Modbus: configuración

          shared_memory=c:\automation\shm\plc1.shm
mailbox=c:\automation\mbx\plc1.mbx
communication=socket          # socket (Modbus TCP) o serial (RTU / ASCII)
tcpadr=192.168.1.20
tcpport=502
#tty=COM1  baudrate=9600  parity=0  protocol=0

          8.2La forma clásica: ciclos

          Se sigue pudiendo usar como antes: cada cycle lee un bloque fijo de registros.

          cycle1 slave=1 function=3 start_adr=0 num_register=50

          En el pvserver se lee por posición: PLC1.readShort(PLC1_CYCLE1_BASE, 49). Los proyectos existentes funcionan sin cambios. La forma recomendada ahora son los tags (capítulo siguiente): se pueden combinar con los ciclos en el mismo archivo.

          8.3Compilar el daemon

          Compilar genera el código y lo compila en su propia ventana (como Ctrl+M), con MinGW o Visual Studio según el compilador elegido: pvdevelop no queda bloqueado mientras compila. Si el daemon está en ejecución, la ventana pregunta si se lo cierra (su .exe no se puede reemplazar mientras corre). Cerrar guarda el archivo y compila solo si cambió desde la última compilación (o si falta el .exe). En Windows lo hace win-mingw\bin\pvb_make_daemon.bat nombre [ppi]; en Linux, una ventana xterm.

          8.4Mensajes en la consola

          El daemon numera sus ciclos. En el editor de tags, Consola del daemon elige qué escribe en su ventana (console= en el archivo):

          NivelQué muestra
          Silencioso (quiet, -q)Solo errores: cuando un bloque deja de leerse y cuando vuelve, y los errores de escritura.
          Normal (normal, -n)Lo mismo y un resumen cada console_interval segundos (10).
          Detallado (verbose, -v)Cada bloque leído con el número de ciclo, el esclavo, la dirección, el resultado y lo que tardó; y el fin de cada ciclo.
          [ciclo 1234] bloque 2/5 esclavo 1 FC3 40300..40301 ok 1 ms
[ciclo 1234] fin: bloques ok=5 error=0, 3 ms
[ciclo 1300] 66 ciclos en 10 s, ultimo 1 ms (max 12), bloques ok=5 error=0, errores lectura=0 (0 nuevos) escritura=0

          Al ejecutar el daemon, -q, -n o -v cambian el nivel sin volver a compilar.

          8.5Tags de sistema

          Los daemons Modbus y Siemens dejan al final de la memoria compartida el estado de la comunicación. pvdevelop los agrega al .h como PLC1_SYS:

          TagTipoSignificado
          ComunicacionboolTodos los bloques del último ciclo se leyeron bien
          ComunicacionParcialboolAlgún bloque se leyó bien y alguno falló
          ConectadoboolConexión abierta (socket o puerto serie)
          BloquesOk, BloquesErroruintResultado del último ciclo
          CicloudintNúmero de ciclo
          TiempoCiclo, TiempoCicloMaxudintDuración del último ciclo y la máxima, en ms
          ErroresLectura, ErroresEscrituraudintContadores desde que arrancó el daemon
          UltimoErrordintCódigo del último error (0 = ninguno)
          UltimaLecturaOk, InicioudintHora de la última lectura correcta y del arranque (segundos desde 1970, UTC)
          Esclavo<n> / Plc<n>boolEl esclavo Modbus o el PLC S7 n respondió en el último ciclo
          if(!PLC1.getBool(PLC1_SYS.Comunicacion)) pvSetText(p, lbEstado, "Sin comunicacion");
if(!PLC1.daemonAlive(PLC1_SYS.Ciclo))     pvSetText(p, lbEstado, "El daemon no esta funcionando");

          daemonAlive(tag, segundos) (5 por defecto) indica si Ciclo avanzó en esos segundos: si el daemon se detiene, los demás tags quedan con su último valor. Sin prefijo: SYS.Comunicacion (con using namespace tags_PLC1;).

          Los tags de sistema van después de los ciclos y de los tags: la memoria compartida crece, y el daemon y el pvserver se compilan con el mismo .h, como siempre.

          8.6Simulación

          Para probar con un simulador sin cambiar la IP ni recompilar, en el mismo .mkmodbus:

          tcpadr=192.168.1.20               # el PLC
simulation_tcpadr=127.0.0.1       # el simulador
simulation_tcpport=502

          El daemon ejecutado con -sim (o con la variable de entorno PVB_SIMULATION=1) se conecta al simulador; sin eso, al PLC. Los tags, la memoria compartida y el .h son los mismos, así que el pvserver no cambia. Sirve también con un daemon serie (RTU): en simulación usa Modbus TCP. Ya no hace falta un segundo archivo (PLC1_Simulacion.mkmodbus) con otros nombres de tags. Al abrir Daemon > Modbus se carga el primer .mkmodbus de la carpeta del proyecto (con Abrir se elige otro).

          8.7Monitor de tags

          Daemon > Monitor de tags... muestra en vivo el valor y la calidad de los tags de cada daemon (lee los .tagmap y la memoria compartida), con un filtro por nombre: sirve para depurar sin tocar el pvserver. Los botones Iniciar daemon e Iniciar en simulación lo ejecutan en su ventana, normal o con -sim. También está en el icono de la barra Proyecto, en el Designer y en el editor.

          Arriba se elige el Daemon (un .tagmap de la carpeta del proyecto) y el Filtro; Pausa congela la tabla. Columnas: Tag, Valor, Calidad, Forzado, Tipo, Descripción (clic en el título ordena). La calidad es bien, error o detenido: si SYS.Ciclo no avanza en 5 segundos el monitor avisa en rojo DAEMON DETENIDO y los valores son los últimos que dejó el daemon.

          Escribir y forzar valores

          Elegir un tag de la lista, escribir el Valor y usar:

          BotónQué hace
          EscribirEscribe el valor una vez (el PLC puede cambiarlo después).
          ForzarVuelve a escribir el valor cada vez que cambia (a lo sumo una vez por segundo) hasta Liberar o cerrar el monitor. La fila queda amarilla y la columna Forzado lo indica.
          Liberar / Liberar todosDeja de forzar el tag elegido o todos.

          Solo se pueden escribir los tags rw=1. La primera vez de cada sesión pide confirmación, porque con el daemon real (sin simulación) se escribe en la máquina. Escribir y Forzar solo se habilitan si el daemon se compiló con esta versión de pvdevelop (el .tagmap trae mailbox= y las direcciones); si no, la línea de estado lo dice: volver a compilar el daemon. Las escrituras van por el mailbox del daemon, igual que las del pvserver.

          09Tags: variables con nombre

          Un tag es una variable del PLC con nombre, dirección y tipo. pvdevelop agrupa las direcciones contiguas o cercanas en bloques y el daemon lee cada bloque en un solo pedido (como los SCADA comerciales).

          9.1Editor de tags

          En la ventana del daemon, botón Tags.... La pestaña Variables tiene la tabla de tags y los ajustes; la pestaña Estructuras define tipos compuestos (capítulo 10). El botón Verificar muestra los bloques de lectura. Las variables se pueden guardar en el archivo del daemon o en un CSV (editable con Excel); Importar/Exportar CSV también está disponible.

          El selector Daemon de arriba lista los daemons del mismo protocolo que hay en la carpeta del proyecto: al elegir otro, el editor pregunta si se guardan los cambios y abre los tags del otro daemon sin pasar por su ventana.

          9.2Notación de direcciones (Modbus)

          NotaciónHolding registerBit de registroInput registerCoilEntrada discreta

          Al cambiar la notación en el editor, las direcciones de la tabla se convierten solas.

          9.3Columnas

          9.4Escritura de bits

          Escribir un bit de un holding register (40300.15) se puede hacer de dos formas (ajuste Escritura de bits):

          • Leer-modificar-escribir (por defecto): el daemon lee el registro, cambia el bit y lo escribe. Sirve con cualquier PLC.
          • Función 22 (Mask Write Register): el PLC cambia el bit. Solo si el PLC la tiene.

          9.5En el archivo .mkmodbus

          address_notation=modicon

tag name=FlagTWR address=40300.15 rw=1 desc="Control desde torre"
tag name=Caudal  address=40311 type=real rw=1

tags=PLC1_tags.csv            # opcional: más tags en un CSV

          Columnas del CSV: name;address;type;count;stride;rw;slave;scan;scale;offset;order;description

          9.6Cómo lee el daemon

          Ciclos y tags a la vez

          Los cycle y los tag se usan al mismo tiempo. En cada vuelta el daemon:

          1. lee los cycle, en orden (sus datos van al principio de la memoria compartida, PLC1_CYCLE1_BASE, ...);
          2. actualiza el contador de vida y los de errores;
          3. lee los bloques de los tags (los que tienen scan solo cuando les toca);
          4. espera, si hace falta, para que la vuelta dure al menos cycletime ms.

          Sin tags el daemon funciona igual que antes (genera la misma memoria compartida). Si solo se usan tags, conviene borrar los cycle: la plantilla trae ciclos de ejemplo para los esclavos 1 a 7, y un esclavo que no existe hace esperar el tiempo de respuesta en cada vuelta, lo que frena también la lectura de los tags. Si ciclos y tags leen los mismos registros, se leen dos veces (funciona, pero es tráfico de más).

          Escala y Offset

          valor = crudo × Escala + Offset. Se aplica en getReal() y, al revés, en setReal(); getInt() devuelve el valor crudo. Ejemplos:

          El PLC mandaEscalaOffsetResultado
          Décimas de grado (253)0.1025.3
          0 a 27648 para −50 a 150 °C0.0072338−5027648 → 150
          Milésimas de bar0.00101500 → 1.5

          Scan y agrupamiento

          Dos tags se leen en el mismo pedido solo si coinciden en esclavo, área (holding, input, coil, discreta; en S7 el área y el número de DB) y scan. Tags contiguos con distinto scan van en pedidos separados, cada uno a su ritmo:

          tag name=A address=%MW0              # scan 0
tag name=B address=%MW1              # scan 0     -> A y B: un pedido en cada vuelta
tag name=C address=%MW2 scan=1000    # otro pedido, cada 1 s

          El scan es un mínimo: el bloque se lee en la primera vuelta en que pasaron al menos esos milisegundos. Si una vuelta dura 300 ms, un tag con scan=1000 se lee cada 1200 ms aproximadamente, y un scan menor que la vuelta es como 0. El botón Verificar muestra los bloques y cada cuánto se lee cada uno.

          Tiempos: puerto serie y TCP

          El daemon hace un pedido a la vez. Cada pedido tarda:

          • la espera antes del pedido (idletime): en serie, 3,5 caracteres como pide Modbus RTU (4 ms a 9600 baudios, 2 ms como mínimo); con TCP, 0;
          • la transmisión: a 9600 baudios cada byte tarda alrededor de 1 ms (leer 8 registros: unos 30 ms);
          • la respuesta del esclavo: típicamente 5 a 20 ms.

          Por eso agrupar ayuda tanto en serie: 8 registros contiguos en un pedido tardan unos 40 ms; en 8 pedidos, unos 300. El scan no acelera la comunicación: reparte el tiempo, dejando la línea libre para los valores que se leen en cada vuelta. Las escrituras también ocupan la línea.

          Ajustes del .mkmodbus:

          AjustePor defectoPara qué
          idletime=serie: 3,5 caracteres; TCP: 0ms antes de cada pedido. Para equipos lentos o conversores serie/Ethernet que lo necesiten (idletime=41 es la espera de las versiones anteriores a 9600 baudios).
          cycletime=50Duración mínima de una vuelta en ms: el daemon no lee más seguido que esto (no satura el PLC ni la CPU). cycletime=0: sin pausa.

          9.7Dirección en el PLC

          El monitor de tags muestra, en la columna Dirección, dónde está cada tag en el PLC: %MW0.0 (Modbus) o DB10.DBX0.1 (Siemens). El daemon la escribe en el .tagmap (plcaddr=); una estructura muestra la de su primer miembro. El filtro del monitor también busca por dirección. Hay que regenerar los daemons para que los .tagmap la traigan.

          9.8Ordenar las tablas

          En el editor de tags (las tablas de tags y de miembros de las estructuras) un clic en el título de una columna ordena por ella; otro clic invierte el orden.

          • El orden es numérico o natural (Motor2 antes de Motor10) y las celdas vacías van al final. Los combos y las casillas ordenan por su valor.
          • Ordenar solo cambia la vista: el orden de los tags en los archivos no cambia, salvo que se use Subir o Bajar.

          10Estructuras y arreglos

          10.1Arreglos

          Con Cantidad > 1 la variable es un arreglo: Temp[0], Temp[1], ... con direcciones consecutivas, o cada Paso registros (bytes en S7). En arreglos de bits el paso es en bits.

          tag name=Temp   address=40100   type=real count=10            # Temp[0..9]: 40100, 40102, ...
tag name=Alarma address=40200.0 type=bool count=32            # 32 bits: 40200.0 ... 40201.15
tag name=Nivel  address=40300   type=int  count=4 stride=10   # 40300, 40310, 40320, 40330

          10.2Estructuras

          Una estructura es un tipo compuesto, como los UDT de los PLC. Se define una vez (pestaña Estructuras) y se usa como tipo de una o varias variables. Cada miembro tiene una Posición relativa al comienzo (registros en Modbus, bytes en S7; con .bit para un bool). Sin posición, el miembro va a continuación del anterior (los bool siguientes ocupan el bit siguiente).

          struct name=Motor desc="Motor de bomba"
member name=Marcha    at=0.0 type=bool rw=1
member name=Falla     type=bool              # 0.1 (a continuación)
member name=Velocidad at=2   type=real rw=1
member name=Corriente type=int scale=0.1     # 4
member name=Alarma    type=bool count=3      # 5.0, 5.1, 5.2
end
tag name=Bomba1 address=40500 type=Motor
tag name=Bombas address=40600 type=Motor count=4 stride=10    # un motor cada 10 registros

          En el pvserver:

          float v = PLC1.getReal(PLC1_Bomba1.Velocidad);
PLC1.setBool(PLC1_Bombas[2].Marcha, 1);
for(int i=0; i<PLC1_Bombas_COUNT; i++)
  pvPrintf(p, Tabla, ...);   // recorrer el arreglo

          Las posiciones no tienen que ser consecutivas (puede haber huecos) y las estructuras se pueden usar en varias variables o en arreglos. Cada estructura se lee en un solo bloque si sus miembros están cerca.

          10.3Estructuras compartidas entre daemons

          Si un proyecto tiene varios daemons (por ejemplo dos PLC Modbus y un Siemens) con el mismo tipo de equipo, la estructura Motor se define una sola vez: en la pestaña Estructuras del editor de tags, marcar Compartida con los otros daemons del proyecto. La estructura se guarda en <proyecto>.mkstruct y cada archivo de daemon recibe una línea structs=<proyecto>.mkstruct; si el daemon tiene una estructura propia con el mismo nombre, esa tiene prioridad.

          # pvs.mkstruct
struct name=Motor desc="Motor de bomba"
member name=Marcha    type=bool rw=1
member name=Falla     type=bool
member name=Velocidad type=real rw=1
end

          Con la columna En (posición) vacía, la misma estructura sirve para cualquier protocolo (Modbus y Siemens): los miembros van uno a continuación del otro.

          DirecciónTipo por defecto

          12Uso de los tags en el pvserver

          12.1Preparar el proyecto

          1. En pvapp.h: #include "PLC1.h" (el .h que genera pvdevelop).
          2. En main.cpp, una vez: rlModbusClient PLC1(PLC1_MAILBOX, PLC1_SHARED_MEMORY, PLC1_SHARED_MEMORY_SIZE);
            (Siemens: rlSiemensTCPClient; mismos argumentos).
          3. En cada maskN_slots.h que lo use: extern rlModbusClient PLC1;
          4. Con RLlib > Descomentar rllib se agregan las bibliotecas al .pro.
          5. El daemon tiene que estar ejecutándose (en Windows desde una consola, o como servicio).

          12.2Funciones

          FunciónDevuelve / hace
          getBool(tag)0 o 1
          getInt(tag) / getUInt(tag)Entero, sin escala
          getReal(tag)Valor con la escala del tag (cualquier tipo)

          12.3El prefijo PLC1_ y los tags sin prefijo

          Las variables se llaman PLC1_<nombre> (el nombre del daemon y un guión bajo) por dos motivos: en cada máscara los widgets también son nombres de C++ (Temp, Motor1, ...) y suele haber una variable y un widget que se llaman igual; y un proyecto puede tener varios daemons con tags del mismo nombre (PLC1_Marcha, PLC2_Marcha).

          Para escribir solo el nombre, el .h trae los mismos tags en el namespace tags_PLC1:

          using namespace tags_PLC1;               // en la máscara (maskN_slots.h)

float t = PLC1.getReal(Temp);
PLC1.setBool(Bombas[2].Marcha, 1);
for(int i=0; i<Temp_COUNT; i++) ...

          Si un nombre coincide con un widget de esa máscara, el compilador avisa (reference to 'Temp' is ambiguous); ahí se usa la forma completa, PLC1_Temp o tags_PLC1::Temp. También se puede usar tags_PLC1::Temp sin el using.

          13Acciones y animaciones de los widgets (Tags...)

          Un botón puede escribir un tag, una etiqueta puede mostrar el valor de un tag y un dibujo puede cambiar de color sin escribir una sola línea de código: se configura en el Designer y pvdevelop genera el código. Todo lo que sigue es para pvservers en C/C++ (no para Lua) y funciona igual en Windows, Linux.

          13.1Abrir el diálogo

          1. En el Designer, Alt+clic sobre el widget (o clic derecho > Properties): se abre Propiedades.
          2. Botón Tags.... Si el widget ya tiene enlaces el botón muestra una marca ✓ y un resumen.
          3. El diálogo Acción y animación de <widget> tiene dos pestañas: Acción (qué pasa al usar el widget) y Animación (cómo se ve según los tags).
          La lista de tags sale de los archivos .tagmap de los daemons. Si está vacía, el diálogo avisa No hay tags: compilar antes el daemon (Daemon > Modbus / Siemens TCP, botón Compilar) para que se genere. Un tag se elige como Fuente:nombre (por ejemplo PLC1:Motores[0].Marcha); el cuadro permite escribir parte del nombre para filtrar.

          13.2Pestaña Acción

          Grupo Al usar el widget: tres filas, Al hacer clic, Al presionar y Al soltar. En cada una se elige la acción, el tag y, según la acción, un valor o una pantalla.

          AcciónQué hace
          NadaNo hace nada.
          Escribir valorEscribe el valor fijo en el tag (write:PLC1:Bomba=1).
          Alternar (bool)Invierte el tag (toggle:PLC1:Bomba).
          Sumar / RestarSuma o resta el valor al tag (para botones + y −); respeta los límites mínimo y máximo.
          Ir a pantallaCambia a la máscara indicada (goto:3).
          Volver / InicioVuelve a la pantalla anterior o a la primera.

          El botón Pulsador momentáneo completa las tres filas para escribir 1 al presionar y 0 al soltar (por ejemplo "marcha mientras se mantiene apretado").

          Opciones

          El slot del widget sigue disponible.           13.6Ejemplo paso a paso: botón de marcha con indicador

          1. Compilar el daemon (PLC1) para tener sus tags.
          2. En el Designer insertar un PushButton btnBomba y una etiqueta lblBomba.
          3. btnBomba > Propiedades > Tags...: Pulsador momentáneo con el tag PLC1:Bomba; Nivel mínimo 1.
          4. lblBomba > Tags... > Animación: Texto PLC1:Bomba con formato Parada|En marcha; Color 0=#808080;1=#00C000.
          5. Ctrl+S, Ctrl+M (compilar) y Ctrl+T (ejecutar). Abrir pvbrowser con Ctrl+P.
          Un pvbrowser anterior a esta versión ignora las órdenes nuevas (franja de alarmas, animación de imágenes) sin dar error; el resto funciona.

          13.7Bits de enteros y condiciones

          Una pantalla puede usar un bit de un entero como si fuera un tag: PLC1:Estado.3 es el bit 3 de PLC1:Estado. Sirve en textos, colores, visible, parpadeo, animaciones y en las acciones toggle: y write:.

          • Lectura: enteros de tipo byte, int, uint, dint y udint. Escritura: solo de 8 y 16 bits. En Modbus se escribe con Mask Write; en Siemens, en el byte dirección + tamaño-1-bit/8 (el bit 10 de DBW300 es DBX300.2).
          • pvdevelop avisa en el ATENCION de maskN_pvb.h si el bit es de un real o un bool, está fuera de rango, o se quiere escribir un bit de 32 bits.
          • En un Modbus con orden de bytes BADC o DCBA, el bit de un registro se escribe como bit del registro, no del valor reordenado.

          Condiciones

          Donde la pantalla pide una condición (Animar mientras, Visible, Parpadeo y el solo si de las acciones) se puede escribir:

          CondiciónSe cumple cuando
          PLC1:Bombael tag es verdadero (distinto de cero)
          !PLC1:Bombael tag es falso
          PLC1:Estado == 2comparación con un valor: ==, !=, >=, <=, >, < (un solo = vale como ==)
          PLC1:Estado.3el bit 3 del entero está en 1

          14Imágenes embebidas

          Normalmente las imágenes se distribuyen como archivos junto al pvserver y pvbrowser las descarga. Con imágenes embebidas quedan dentro del ejecutable: no hace falta copiar la carpeta de imágenes a la PC de producción y nadie las puede cambiar o borrar.

          14.1Cómo usarlas

          • Una imagen: Propiedades del widget > casilla Embeber imagen.
          • Todas juntas: Acción > Recursos del proyecto.... La tabla tiene las columnas Embeber, Archivo, Tamaño (ordenable) y Usada en. Los botones Marcar las usadas (las que usan las máscaras), Todas y Ninguna ayudan; Guardar graba la lista.
          • Al elegir una imagen de cualquier carpeta en las propiedades, pvdevelop ofrece copiarla a la carpeta Image/ del proyecto.

          La lista se guarda en <proyecto>.pvres (un archivo por línea). En cada compilación pvdevelop genera pvresources.cpp con los datos (y lo agrega al .pro) solo si algo cambió. En ejecución el pvserver manda la imagen embebida a pvbrowser una vez por conexión, como archivo temporal, y pvbrowser lo borra al cerrar.

          # Archivos embebidos en el pvserver (pvdevelop: Accion > Recursos del proyecto)
imagenes/off.png
imagenes/on.png
imagenes/luz.gif

          14.2Animación de imágenes

          La animación la hace pvbrowser (no hay tráfico mientras anima). Se configura en Tags... > Animación > Animar mientras (ver 13.3) o desde el código:

          pvSetImageAnimation(p, Bomba, "bomba1.png,bomba2.png,bomba3.png", 300);   // cuadros y período en ms

          Los .gif animados se reproducen solos. Esto vale solo para pvservers en C/C++.

          15Compilar la suite

          Solo para quien modifica PV Suite. Hace falta Qt 6.9 (probado con 6.9.2). Se compila con qmake, en una carpeta aparte (build/, fuera de git); también se pueden abrir los .pro en Qt Creator, cada uno con su kit.

          SistemaProyectoQué compila
          Linux y macOSpvsuite.proTodo, pvbrowser incluido.
          Windows (MinGW)pvsuite.proTodo menos pvbrowser: rllib, qwt, pvserver, pvdevelop y las herramientas.
          Windows (MSVC 2022)msvc/pvbrowser-msvc.propvbrowser (Qt WebEngine no existe para MinGW), rllib.lib y serverlib.lib, para compilar pvservers con Visual Studio.

          Linux y macOS

          mkdir build && cd build
~/Qt/6.9.2/gcc_64/bin/qmake ../pvsuite.pro CONFIG+=release    # macOS: ~/Qt/6.9.2/macos/bin/qmake
make -j8

          Windows

          En Windows se usan los dos proyectos: la suite con MinGW y pvbrowser con MSVC.

          rem consola con C:\Qt\Tools\mingw1310_64\bin y C:\Qt\6.9.2\mingw_64\bin en el PATH
mkdir build\mingw && cd build\mingw
qmake ..\..\pvsuite.pro CONFIG+=release
mingw32-make -j8

rem consola "x64 Native Tools" de Visual Studio 2022 con C:\Qt\6.9.2\msvc2022_64\bin en el PATH
mkdir build\msvc && cd build\msvc
qmake ..\..\msvc\pvbrowser-msvc.pro CONFIG+=release
nmake

          Las bibliotecas quedan junto a sus fuentes (rllib/lib, pvserver, qwt/lib). En Windows, pvdevelop necesita qwt/lib/qwt.dll y pvbrowser msvc/qwt-msvc/lib/qwt.dll junto al .exe.

          16Solución de problemas

          SíntomaCausa y solución
          El pvserver se cierra sin mensaje al abrir pvbrowser o al refrescar (Ctrl+R). Archivos que no se encuentran (ejecutar desde la carpeta del proyecto, no desde release); un fopen sin verificar; o funciones dentro de DATA sin namespace { } (ver 5.2). Para ver dónde falla: compilar con QMAKE_CXXFLAGS_RELEASE += /Zi y QMAKE_LFLAGS_RELEASE += /DEBUG y ejecutar con cdb -g -G .\release\pvs.exe; ante el error escribir kb.
          'QString' file not found al compilar con MSVC.El proyecto usa Qt: configurar "Qt para MSVC" en Acción > Compilador.
          símbolo externo __imp_ShellExecuteA sin resolverAgregar LIBS += -lshell32 en el bloque win32-msvc* del .pro.
          Qt WebEngine no existe para MinGW en Qt CreatorAbrir pvbrowser-www-msvc.pro con el kit MSVC (pvbrowser con web solo compila con MSVC).
          Errores de codificación (C4828, C2001) con MSVCArchivos en Latin-1: convertirlos a UTF-8, o agregar CONFIG -= utf8_source.
          Un tag siempre con quality() = 0El daemon no está ejecutándose, el PLC no responde, o la dirección no existe en el PLC (verificar con Verificar los bloques).
          Valores real absurdosOrden de palabras: probar CDAB en lugar de ABCD.
          Al compilar el daemon: cannot open output file ... Permission deniedEl daemon está en ejecución: cerrarlo (la ventana de compilación lo ofrece) y compilar de nuevo.
          Los tags de sistema (PLC1_SYS) no cambianEl daemon no está funcionando o espera la conexión: ver daemonAlive(PLC1_SYS.Ciclo) y la ventana del daemon (con -v).
